# Phase 3: Bias-Aware Model Training

This repository builds a fairness-constrained churn prediction pipeline for
financial-strain risk assessment. The trainer combines preprocessing,
class-balanced random forest classification, sigmoid probability calibration,
regional recall auditing, and optional SHAP explanations.

The model is a decision-support tool only. It must not be used for automatic
loan denial or any other automated adverse financial decision.

## Repository Layout

```text
.
├── data/processed/engineered_features.csv  # Milestone 2 input dataset
├── model_trainer.py                        # Training and validation script
├── models/churn_pipeline.pkl                # Generated approved pipeline
├── reports/model_card.md                    # Generated documentation
└── requirements.txt                         # Python dependencies
```

The `models/` and `reports/` files are generated by the script and should be
reviewed before they are shared or deployed.

## Setup

Use Python 3.9 or newer and install the project dependencies:

```bash
python -m pip install -r requirements.txt
```

The bundled input file is a small deterministic demo dataset at:

```text
data/processed/engineered_features.csv
```

Replace this demo CSV with the complete Milestone 2 engineered export before
submission or any real evaluation. The demo exists so a clean clone can run
the training contract end to end without requiring private customer data.

The CSV must contain:

- A `region` column used for subgroup auditing. Region values are normalized
  case-insensitively, so `Township` and `township` are treated alike.
- A binary target column named one of `churn`, `churned`, `churn_flag`,
  `target`, `label`, or `y`.
- One or more numeric or categorical feature columns.

Do not include the target column among the feature columns. The dataset should
contain at least two examples of each target class and positive examples in
each region that is expected to be audited.

## Run

From the repository root, run:

```bash
python model_trainer.py
```

On success, the script:

1. Infers the target column and separates it from the features.
2. Builds a `ColumnTransformer` with median numeric imputation and
	most-frequent categorical imputation followed by one-hot encoding.
3. Fits a class-balanced random forest inside
	`CalibratedClassifierCV(method="sigmoid")`. Sigmoid calibration is the
	Platt-style calibration required for reliable risk probabilities.
4. Calculates cross-validated recall for every region.
5. Generates SHAP-based explanations for the three most influential features
	when the `shap` package is available.
6. Writes the model card and serializes the approved pipeline.

Generated files:

```text
models/churn_pipeline.pkl
reports/model_card.md
```

Load the serialized pipeline with standard pickle support:

```python
import pickle

with open("models/churn_pipeline.pkl", "rb") as stream:
	 pipeline = pickle.load(stream)
probabilities = pipeline.predict_proba(new_features)[:, 1]
```

## Fairness Gate

The audit uses cross-validated predictions rather than predictions from the
same fitted rows. For each region with positive examples, it computes recall
and then calculates:

```text
maximum regional recall - minimum regional recall
```

The maximum permitted disparity is `0.15` (15 percentage points). If the
disparity is greater than 15%, or if the audit cannot be calculated, training
raises an error and `models/churn_pipeline.pkl` is not written. A model card
is still written to support investigation and remediation.

The string representation reports the audit in the requested format:

```text
Recall: 82% (Township: 78% | Urban: 85%) | Max disparity: 7%
```

Missing subgroups are reported as `N/A`; the trainer never treats an absent
group as having zero recall.

## Ethical Safeguards

The generated model card includes the exact warning:

```text
⚠️ NEVER use for automatic loan denial
```

Additional safeguards include:

- Human review for every high-risk prediction.
- No automated exclusion, pricing, or denial of financial services.
- Monthly regional recall and calibration audits.
- Monitoring for data drift, missingness, subgroup sample size, and changing
  economic conditions.
- Quarterly retraining review rather than unexamined automatic retraining.

## Limitations and Failure Modes

Model probabilities are estimates of association, not causal explanations or
evidence that a customer can repay. Performance may degrade when economic
conditions, product mix, data collection, or customer populations change.
Historical labels can reproduce structural disadvantage, and small or
unrepresented communities may have unstable metrics. Customers with less than
three months of history are especially uncertain.

SHAP explanations describe model behavior and do not establish why a person
will churn. Explanations must be reviewed alongside customer context by a
qualified human reviewer.

At minimum, compile the script and check patch formatting before submission:

```bash
python -m py_compile model_trainer.py
git diff --check
```

For a complete local validation, install the requirements, add the Milestone 2

for any approved decision-support use.
